CV Data Extractor — Borderless PDF to Excel
PythonpdfplumberData Extraction
2025–2026 · Personal Automation Tool · Check Voucher Processing
Context
Problem: Check Voucher (CV) summary reports come out of the source system as text-based PDFs with no visible table gridlines, so standard table-extraction approaches fail. Manually retyping CV numbers, payees, and amounts into Excel was slow and error-prone.
Client/Use: Internal tool for converting CV summary PDFs into itemized Excel data for reconciliation and record-keeping.

Role
Responsibilities: Sole developer. Designed the position-based parsing logic since there were no borders to key off of.
Tools: Python, pdfplumber, pandas.

Process
Words are grouped into lines by vertical position rather than relying on table borders. Header rows are detected by keyword ("CV NUMBER", "AMOUNT", "CHECK"), and their word x-positions become column boundaries that every subsequent data row is bucketed against. Key Challenge: "DATE TRANS" headers are frequently separated from their table by a page break, so the script carries the current date forward continuously across pages until a new date header appears. Subtotal rows, blank rows, and wrapped headers are auto-skipped via pattern matching on the CV number format.

Results
Reliable extraction of Date Trans, CV Number, Payee, Gross Amount, and Net Amount from borderless PDFs directly into a clean Excel file, with zero manual retyping. Context
Problem: CV summary PDFs have zero gridlines. No borders, no mercy, just text floating in vaguely column-shaped regions. Retyping that by hand into Excel is not a task, it's a punishment.
Client/Use: Built for myself, to stop doing exactly that.

Role
What I did: Wrote a parser that figures out "columns" from word positions since the PDF refuses to admit columns exist.
Tools: Python, pdfplumber, pandas.

Process
Group words into lines by vertical position. Find the header row by keyword, steal its x-coordinates as column boundaries, bucket every row after it against those boundaries. The annoying part: date headers get orphaned from their table across page breaks, so the script just remembers the last date it saw and keeps using it until told otherwise, like a very committed intern.

Results
Feed it a borderless PDF, get back a clean itemized Excel file: Date, CV Number, Payee, Gross, Net. No more manually transcribing numbers into a spreadsheet at 11pm.

Role

Tools: Python, Ollama (local model + cloud tier), Claude API (via this portfolio's chatbot), Markdown, Obsidian + Dataview, Git, bash batch files.

Process
Built three layers that cooperate: (1) a Markdown vault under hard rules (lowercase-kebab-case tags, wikilinks capped at 3-5 per note, no invented facts), (2) Python tooling that proposes small appends under `## 🤖 AI Updates` sections rather than overwriting, with y/n approval per change, (3) a separate `public_brain.md` file as the only thing the public-facing chatbot ever reads, so private notes can never leak by accident.
Key Challenge: Memory and resource constraints. Solved by reading `index.md` (one line per note) instead of full files when possible, batching changes, and using a small local model (`qwen2.5-coder:1.5b-instruct`) plus a cloud fallback for heavier reasoning — the whole thing runs on an 8GB machine.

Results
A working personal knowledge system with an enforced action model (append or create, never overwrite), built-in lint that catches broken links and orphans weekly, and a clean separation between private notes and public chatbot knowledge.
